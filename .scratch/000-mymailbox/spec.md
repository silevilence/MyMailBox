## 已确定的技术与发布约束

- Avalonia、C#、.NET 10、Windows x64；全部 JIT、框架依赖发布，由用户安装系统 .NET Runtime，不打包自包含运行时，不启用 NativeAOT 或裁剪。
- 插件框架优先复用 CordiSharp，在适配层完善依赖、生命周期和失败恢复。内置与外部实现使用同一公开契约。
- 核心插件启动时由 Profile 固定，不在运行中更换；普通插件支持受约束的热加载、卸载和配置重载。核心/普通与内置/外部是不同分类，两类配置分两个文件。
- NSIS 安装；GitHub Releases 为更新源。更新检查优先验证 NetSparkle / Octokit，确不适配时直接调用 API；在实施对应任务时才收集缺失仓库地址。
- 发布流程：generate-changelog 生成用户变更记录并同步版本 → 提交 → V/v Tag → push → Actions 自动检查、构建、NSIS 打包及完整 Release。当前任务集的创建不等于任何提交、打 Tag、真实外发邮件或发布授权。
- 仅作为背景保留 AOT 对比，不再规划 AOT/WASM 选型实现。

## 产品交付边界

### 邮箱和账户

可添加多个同类型或不同类型账户，具备稳定自动 ID、可选唯一 alias、显示名、tags、颜色、备注、排序和收发能力。账户重命名不破坏自动化引用；账户不等于唯一发送地址。支持 QQ、163、通用 IMAP/SMTP、POP3、Outlook.com、用户实际公司 Exchange 和本地邮箱。按实际能力支持仅收、仅发、目录、配额、标记和搜索，不把协议缺少的能力伪装为已实现。

### Outlook 迁移与导出

在线账户配置导入和 PST 邮件/目录导入为必做，重新授权、字段/项目损失报告及中断恢复属于完成条件。Outlook 版本/位数和真实样本需要在对应验证任务收集。规则导入先做必做可行性评估，再按可转换子集实施；不能丢弃未知条件后启用宽泛规则。非邮件 PST 项目应报告，不自动扩展为完整联系人/日历替代。

多形式导出包括 EML、可恢复归档、PDF/HTML/文本、附件及元数据。额外迁移格式与 MSG/PST 写入列为可选。工作空间备份与单封邮件导出是不同交付物；导出配置不默认包含秘密。

### 阅读发送与同步

具备安全 MIME/HTML 阅读、多语言与损坏内容回退、附件处理、远程多媒体默认阻断和按范围放行。编辑器提供富文本/纯文本、To/Cc/Bcc、身份、附件/内联图、签名、草稿、回复转发和持久发件箱。支持自动接收、增量同步、离线、限流、过期授权与多客户端冲突恢复。

### 搜索与自动化

搜索、收件规则及任务选择共享版本化条件语义，支持收发件人（包括 Cc）、标题、正文、日期、大小、状态以及 AND/OR/NOT、分组、字符串匹配和受限正则。未知内容或缺失插件不能被 NOT 翻转为可执行删除条件。

任务模型固定为“调度/事件 → 任务前置条件 → 目标邮件选择 → 有序动作 → 结果与恢复”。触发账户与被处理账户可以不同。调度覆盖一次、间隔、日/周/月/年、第 N 或最后一个周几、CRON、时区与补跑。条件包括数量、大小、配额、邮件存在等聚合；动作包括移动/复制/归档/标记/导出/提醒及受控扩展。必须完整演示“超过 30 天邮件到本地归档”和“邮箱 1 的阈值触发处理邮箱 2”的场景。

跨邮箱移动先持久化并验证完整目标，再清理来源；失败可恢复、不丢唯一副本。不能承诺所有远端目标均支持原样导入，也不能用重发邮件冒充迁移。

### UI 性能与扩展规范

UI 围绕阅读、写信、整理与恢复心流设计；选择器支持识别、搜索、能力过滤和稳定引用，不要求用户记 UUID。常见用户操作有及时反馈，大列表与数据均分页/虚拟化，长搜索可取消或替换，旧结果不得覆盖新查询。

每个内置业务能力都需有合适公开接口，最终以第二实现替换验证，不能只用“已有接口”作验收。普通插件默认贡献宿主渲染 UI；复杂 Avalonia 控件须符合经过验证的卸载规范。

## 任务粒度和状态

当前共有 108 项：93 项必做及必要支撑、5 项条件路线/条件实现、10 项可选扩展或范围决策。常见任务目标 2–3 人日，不含外部等待，不是排期承诺。遇到超出目标的实现，在动手前按完整可验收子场景再拆；范围决策只产出证据和后续任务，不能当成功能完成。

- `Status: ready-for-agent`：说明可执行；仍须检查 `Blocked by` 是否完成。
- `Status: needs-info`：缺少必要外部环境、尚未选择条件路线或可选范围。应记录具体缺口；已有信息足够的准备工作可先做，但不能假称集成验收通过。
- `Progress: not-started`：尚未开始。实施时使用 `in-progress`、`blocked`、`done` 记录实际进度；此字段独立于分诊 Status。依赖解除看任务 Progress 与验收证据，不把 ready 标签当完成。
- 每项保持独立 Markdown 文件。评论追加至末尾 Comments；索引和覆盖矩阵同步更新，不把所有任务合并为单个工单。

## 条件路线与外部依赖

### 公司 Exchange

Exchange 接入是通用账户功能：服务器地址、登录账号和认证配置由用户逐账户填写或通过受控自动发现取得，不在产品代码或默认配置中绑定某家公司。公司端点仅用于授权验收。Outlook.com 则共用发布者的公共客户端应用 ID，普通用户仅登录并同意访问自己的邮箱，无需创建应用注册或输入 Client ID。

[35 验证公司 Exchange 的真实接入路径](issues/35-exchange-discovery.md) 是必做验证。其结论决定采用 [36 通过本地 Exchange 提供者浏览并读取邮件](issues/36-ews-read.md)、[37 完成公司 Exchange 的写信和邮件操作](issues/37-ews-send.md)、[38 持续同步公司 Exchange 并恢复断网](issues/38-ews-sync.md) 或 [39 通过 Microsoft 365 组织账户完成收发](issues/39-exchange-online.md)，混合部署按实际邮箱位置组合。若只能使用通用协议降级，须明确用户接受的边界，不能自行删减公司邮箱能力。

[84 联调各提供者的故障与恢复矩阵](issues/84-reliability.md) 和 [98 按原始需求逐项完成发布前验收](issues/98-acceptance.md) 除普通显式依赖之外，还受已选公司路线全部通过的条件门槛约束。实施者须把选定路线写入这两项的依赖并记录依据，未选路线标注不适用理由。任何真实接入任务都不能由模拟或无关个人账号代替验收。

### Outlook 规则

先完成 [54 识别可转换的 Outlook 规则子集](issues/54-rules-import-spike.md)；可转换且纳入范围的子集由 [68 转换并预览可支持的 Outlook 规则](issues/68-rules-import.md) 交付。总验收检查评估结论，并在可行时要求转换结果。若确实无法转换，提供证据、不支持项及手动迁移说明，不伪造支持。

### 实施时才获取的信息

公司端点/版本/认证/VPN、Outlook 版本与位数、测试账户/应用注册、去敏 PST/规则样本、更新仓库和签名材料，均在相应工单写明。当前无需提前索要。需要额外 x86 导入桥、商业库、GUI 完全退出后常驻、整库加密或新功能范围时再进行具体决策，不改写已确认的 win-x64/JIT 发布约束。

## 通用完成标准

1. 交付工单描述的端到端行为，涵盖必要 UI、持久化、插件契约、错误与取消；通过该工单验收。
2. 适当运行契约、集成、故障注入或实际发布验证；文档/低影响改动不机械增加镜像实现的测试。外部环境未就绪不得标真实接入完成。
3. 重要操作保留可定位的结果及脱敏证据。资源释放、来源保留、不可逆边界和重复执行防护符合相关要求。
4. 复用本地依赖、安装包与测试数据。GUI 验收前完成构建和数据准备，集中验证后退出测试进程；在线下载只验证一次，其余复用；发布后用平台摘要与 CI 记录核对。
5. 更新必要用户/开发文档和任务记录，记录已知限制；不把用户未确认的可选范围偷偷变为首版义务。

性能数字以评估文档中的拟定基准为准，记录实际硬件、冷/热缓存、索引状态和后台任务负载。最终总验收还须覆盖所有原始需求及后续确认的发布流程；验收完成并不自动授权发布。
