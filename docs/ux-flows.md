# 桌面交互与原型规范

应用 ui-ux-pro-max 技能，已查询 desktop email workspace 设计方向和 Avalonia keyboard navigation resources。检索的营销落地页结构不适用于桌面工作空间，未采用；下列为针对本产品制定的界面规范。

- 使用 Windows 系统字体（微软雅黑 UI / Segoe UI），正文 14、标题 28；4/8 像素间距，原生 Fluent 按钮、表单与焦点，浅色中性背景。无装饰动画与远程字体下载。
- 左侧稳定导航、右侧当前任务；表单标签在输入框上方，结果紧随操作。窄窗口可纵向滚动，底部状态始终说明配置错误。
- 所有账户选择同时显示名称、地址或本地类型、目录路径；存储稳定 ID，用户不靠颜色或 UUID 识别。发送身份排除仅存储的本地账户。
- 插件操作、配置、诊断属于设置；阅读/写信/自动化/恢复是用户任务。原型明确标注演示数据，不假装真实发信或归档。

## 四条演示路径

1. 阅读：工作/个人/本地账户 → 目录 → 打开模拟邮件；可进入空目录、加载失败、重试状态，结果保留账户和路径。
2. 写信：选择身份 → 输入收件人/主题/正文 → 预览 → 保存并恢复模拟草稿；身份在预览和恢复结果中重复确认。
3. 跨账户自动化：工作邮箱数量 > 1000 → 选择个人邮箱早于 30 天邮件 → 本地年度归档 → 预览 → 模拟执行。条件账户与处理账户分列，修改任何条件后必须重新预览。
4. 恢复：模拟在第 3 封前中断 → 历史展示已完成 2/3 且来源保留 → 从失败步骤继续 → 重复继续保持相同结果。

## 本轮审视与修订

- 易误选问题：触发账户被误当成处理来源。修订为“判定阈值的账户”和“实际处理的账户”，在预览中分行复述来源与目标。
- 易误选问题：本地归档可能出现在发送身份。修订为能力过滤，本地账户仅出现在阅读及归档目标中。
- 易误用问题：改了范围却使用旧预览执行。修订为预览快照比对，提示重新预览。
- 键盘路径：Tab/Shift+Tab 遍历导航、输入及按钮；Space/Enter 激活按钮；方向键切换下拉选择。使用原生控件及 AutomationId 验证。
- 本文是代理的流程审视和定向场景检查，不声称进行过真人可用性访谈。所有本轮任务完成后已集中通过四条真实窗口场景和 Tab 字段导航验收。
