# 可复用的大邮箱性能基线

Windows 11 专业版 26200，Intel Core Ultra 7 165U，物理内存 31.6 GiB，SSD。使用 .NET 10 和项目实际 SQLite、MIME、全文搜索及 IMAP 服务。所有邮件由固定公式在本机生成，使用保留示例域名。测试库、机器清单和逐次测量输出位于 Git 忽略的 artifacts/performance-v1。

| ---: | --- | --- | ---: | ---: | --- | --- |
| 10,000 | 10 / 50 | 40 / 4 | 3,334 | 914 | 738 B / 3,357 B | 15,546 B / 2 MiB |
| 100,000 | 10 / 50 | 40 / 4 | 33,334 | 9,135 | 739 B / 3,333 B | 15,323 B / 2 MiB |

运行 `./scripts/measure-mailbox.ps1 -PrepareOnly` 准备样本。第二次实测分别复用了 10,000 和 100,000 条记录。源库保留未完成的索引，另一份本地 SQLite 备份建立完整索引。启动仓库已有的本机 GreenMail 后执行 `./scripts/measure-mailbox.ps1 -WithSync`，即可重复两种数据量、两种索引状态、同步开关共八组。单独使用 `-Size 10000` 可缩短迭代。可从 `indexed` 父目录作为应用工作空间开展 UI 验收。

每组启动一个新检查进程，分别记录首次操作和随后十次热请求。首次请求是应用级冷启动，Windows 文件缓存沿用当前状态。未索引组测分页、读取和中断首次正文查询，已索引组再测主题、正文首批各 25 封。同步打开时，同一工作区并发运行实际 IMAP UID 同步。各组 JSON 包含完整索引计数、真实同步次数、逐次耗时、进程峰值工作集与 I/O 计数。

| --- | --- | --- |
| 当前目录首批 25 封 | 5 / 27 | 5 / 15 |
| 已缓存普通 MIME 读取和解析 | 4 / 3 | 4 / 3 |

本表为优化前的服务层基准。10 万封两种搜索均超过 2 秒目标，登记在 83。首屏绘制、帧耗时与真实桌面反馈在集中 UI 验收中单独测量。

## 发布程序的桌面实测

2026-11-18，使用同一台机器和上述已索引样本。每组从独立进程启动实际 win-x64 发布程序，后台同时处理一个独立范围内的归档任务。测量从 UI Automation 发出操作到窗口反馈可读的端到端时间，每种操作 10 次，最近秩法计算 p95。每页查询 50 封，测量窗口中实际生成了 5 个列表项。连续 PageDown、PageUp 滚动另记录 Avalonia 帧回调间隔。

| p95（毫秒） | 1 万封 | 10 万封 |
| --- | ---: | ---: |
| 缓存目录翻页 | 94.30 | 84.66 |
| 普通邮件打开并出现正文 | 196.15 | 51.89 |
| 已索引主题搜索首批 | 50.99 | 1,080.76 |
| 取消搜索出现反馈 | 18.19 | 29.42 |
| 滚动帧间隔 | 32.70 | 32.74 |

两组滚动分别取得 147 和 152 个帧间隔，各有 4 个超过 33.33 毫秒，最长为 34.08 和 36.30 毫秒。两组均未出现超过 50 毫秒的滚动长帧。以 60 Hz 的 16.67 毫秒为参考，仍有部分帧跨过一个刷新周期。峰值工作集分别为 432 和 439 MiB。测量阶段进程 I/O 计数分别为读取 138 和 2,391 MiB、写入 712 和 656 KiB，包括缓存文件和系统 I/O。实际归档在两组测量期间分别完成 1 和 2 封。

搜索维护改为按变更增量处理，最新排序的首批查询可以先检查最近日期范围，结果不足仍执行完整查询。只读规则和归档预览按邮件 ID 合并已有索引与临时解析值。10 万封同步开启时，服务层热缓存主题和正文搜索 p95 分别为 11 和 30 毫秒。桌面测试单独计入应用启动后的首轮查询。

复验先运行 `dotnet run --project tests/MyMailBox.Checks --no-build -- perf-prepare-ui 100000`，再运行 `dotnet run --project tests/MyMailBox.UiChecks --no-build -- performance 100000`。1 万封组将参数改为 `10000`。原始读数在 `artifacts/performance-v1/<规模>/ui/ui-measure.json` 和同目录 `frame-ticks.json`。命令复用已建立索引的库，后台归档只处理单独准备的副本。

同日最终回归再次使用原库，准备阶段仅取消上一轮基准自身未处理完的归档批次，再补足来源中的 12 个测试项目。首轮桌面记录保留于 `artifacts/task000-performance-baseline`。复测时 1 万/10 万封的翻页 p95 为 88.83/91.54 毫秒，阅读为 47.35/51.58 毫秒，搜索为 45.80/1,114.85 毫秒，取消为 24.38/10.49 毫秒。后台分别归档 1/2 封。10 万封滚动帧 p95 为 33.16 毫秒，158 个帧间隔中有 6 个超过 33.33 毫秒，最长 40.83 毫秒。
