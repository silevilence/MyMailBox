# 可复用的大邮箱性能基线

Windows 11 专业版 26200，Intel Core Ultra 7 165U，物理内存 31.6 GiB，SSD。使用 .NET 10 和项目实际 SQLite、MIME、全文搜索及 IMAP 服务。所有邮件由固定公式在本机生成，使用保留示例域名。测试库、机器清单和逐次测量输出位于 Git 忽略的 artifacts/performance-v1。

| 邮件数 | 本地账户 / 目录 | 有邮件目录 / 深度 | HTML | 附件 | 平均纯文本 / 原始 MIME | 平均附件 / 最大附件 |
| ---: | --- | --- | ---: | ---: | --- | --- |
| 10,000 | 10 / 50 | 40 / 4 | 3,334 | 914 | 738 B / 3,357 B | 15,546 B / 2 MiB |
| 100,000 | 10 / 50 | 40 / 4 | 33,334 | 9,135 | 739 B / 3,333 B | 15,323 B / 2 MiB |

运行 `./scripts/measure-mailbox.ps1 -PrepareOnly` 准备样本。第二次实测分别复用了 10,000 和 100,000 条记录。源库保留未完成的索引，另一份本地 SQLite 备份建立完整索引。启动仓库已有的本机 GreenMail 后执行 `./scripts/measure-mailbox.ps1 -WithSync`，即可重复两种数据量、两种索引状态、同步开关共八组。单独使用 `-Size 10000` 可缩短迭代。可从 `indexed` 父目录作为应用工作空间开展 UI 验收。

每组启动一个新检查进程，分别记录首次操作和随后十次热请求。首次请求是应用级冷启动，Windows 文件缓存沿用当前状态。未索引组测分页、读取和中断首次正文查询，已索引组再测主题、正文首批各 25 封。同步打开时，同一工作区并发运行实际 IMAP UID 同步。各组 JSON 包含完整索引计数、真实同步次数、逐次耗时、进程峰值工作集与 I/O 计数。

| --- | --- | --- |
| 当前目录首批 25 封 | 5 / 27 | 5 / 15 |
| 已缓存普通 MIME 读取和解析 | 4 / 3 | 4 / 3 |
| 主题查询首批 | 254 / 283 | 3,299 / 3,080 |
| 中文正文查询首批 | 367 / 373 | 3,964 / 4,030 |

本表为优化前的服务层基准。10 万封两种搜索均超过 2 秒目标，登记在 83。首屏绘制、帧耗时与真实桌面反馈在集中 UI 验收中单独测量。
