## 发现并修复的问题

- 取消任务的异常堆栈和委托会持有插件程序集：宿主异步边界转换为宿主错误并释放委托，保留可诊断信息，不向长期任务泄漏插件类型。
- 打开插件页面后，旧控件的 Click 处理器持有页面执行委托：导航离开时显式解绑，真实打开页面后的升级与 30 轮卸载通过。
- 无关插件注册变化重绘当前表单会丢输入和结果：仅在当前页面或选择器提供者实际变化时重建内容。
- 应用关闭不能在 UI 线程同步等待配置监听：关闭流程改为异步等待初始化、停止监听及排空操作，再释放视图和插件。
- 菜单消失只是注册撤销，不代表程序集已释放：验收脚本等待明确的释放结果，不在生命周期尚未完成时判定成功。

## 高级 Avalonia Control 的明确边界

使用 `NativePlugin.AnimatedView` 真实挂载控件，执行 DispatcherTimer、Opacity Transition 和 ResourceDictionary，离开页面时停止计时器、取消事件、清除动画与资源。**Avalonia 12.1.1 仍保留该自定义 Control 类型的程序集引用，不能承诺此类控件热卸载。**

应用显示“资源/程序集释放失败，需要重启”，不显示成功，不覆盖仍使用的版本；此状态下后续配置变更明确要求重启。退出进程可释放这些引用。该实验满足工单 06 对高级能力单独验证、失败如实说明的条件，但不代表任意原生控件已获得热卸载支持。普通插件默认使用已验证的宿主渲染契约。
